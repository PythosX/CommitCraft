Built for deliberate publishing

A publishing workflow you can actually review.

CommitCraft writes to GitHub through the Git Database API. Every selected file becomes its own commit, in the order you choose, with the message you write.

File-by-file commits

Each file is written as a blob, added to a tree, and committed on top of the previous commit. No squashed history, no bundled commit.

Custom commit messages

Write every message yourself, or start from a template and edit from there. A live preview shows the exact plan before anything is committed.

Folder-aware publishing

Nested paths stay nested. assets/images/logo.svg lands exactly there, and the rest of the repository is preserved untouched.

Secure GitHub connection

OAuth runs on the Worker. Your access token is encrypted server-side, held in an HttpOnly session and never exposed to page JavaScript.

Live publishing progress

Watch each file move from waiting to committing to completed, with its commit SHA and a direct link to GitHub.

Resume interrupted publishing

Job state is persisted per file. Close the tab mid-run, come back, and continue without duplicating commits that already landed.

Four steps, no surprises

From folder to real Git history.

Connect GitHub

Authorize CommitCraft with the repository scope. Tokens stay on the server.

Choose a repository

Pick an existing repo and branch, or create a fresh one without leaving the app.

Review your commits

Select files, write messages, reorder the plan and confirm exactly what will happen.

Publish your project

Each file becomes its own commit, in order, with its own SHA you can open on GitHub.

Security is the default

Built to handle your real repository.

CommitCraft never force-pushes and never rewrites history. It checks the branch head before every commit and stops if anything moved underneath it.

Fast-forward onlyBranch updates use force: false, so remote work is never overwritten.
Secrets blockedEnvironment files, private keys and credential stores are refused by both the UI and the API.
No duplicate commitsIf a commit lands before an interruption, recovery detects it instead of committing twice.

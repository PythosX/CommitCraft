Terms of use

CommitCraft publishes files to repositories you control. Use it carefully — Git history is durable.

You own your content

You are responsible for the files you upload and for having the rights to publish them. CommitCraft only writes to repositories your GitHub account can already push to.

What the tool does and does not do

Each selected file becomes one Git commit whose parent is the previous commit or the current branch head. CommitCraft never force-pushes, never deletes existing files, and never rewrites history. It stops if the branch changes underneath it.

No tool is perfect. Verify your repository after publishing, keep backups of important work, and use a test repository the first time you use any publishing tool.

Availability

CommitCraft V1 is provided as-is, without warranty. GitHub rate limits, network failures, revoked authorizations and repository protection rules can interrupt publishing. Failed jobs can be retried and successful commits are preserved.

Acceptable use

Do not use CommitCraft to publish malware, to attempt to access repositories you are not authorized to write to, or to bypass repository protection rules. Do not publish secrets — the API blocks common secret filenames, but it cannot catch every possible secret.
